# Fork offline validation controller

This controller is fork-only. It validates source commit `1601d89e02aa42e3350a23442fba19e3fe3f02b5` from pull request https://github.com/rpridal/paperclip/pull/3. The review base is `3549b7821728c2fdbe8fafa2ca10ba3ebc8b3061`.

The controller commit is not the validated source commit. The workflow checks out the source by its full SHA with persisted credentials disabled. It records source SHA/tree, actual Node/pnpm/Rust versions, UID, command return code, elapsed time and raw logs. It uses GitHub-hosted disposable Ubuntu runners, not a platform runner. It uses Node 24.21.0, pnpm 9.15.4 and genuine Rust 1.97.1 plus rustfmt. Dependency preparation uses a frozen lockfile and real lifecycle scripts. Cargo downloads finish before offline Rust validation.

Three independent bounded jobs execute the unchanged canonical commands: `pnpm -r typecheck`, `pnpm test:run`, and `pnpm build`. Each command has a 40-minute timeout; each job has a 50-minute timeout. Local heartbeat commands remain below 60 seconds. A complete root run provides independent authoritative evidence, not an inflated union of the old partial shard ledger. No previous local shard is repeated in this heartbeat.

The test environment is allowlisted, has no production database URL or service keys, and uses a fresh disposable HOME. GITHUB_WORKFLOW is not passed to the tests, so the source harness retains native-runner coverage rather than excluding it as a PR-special lane. Test summaries with skipped/todo cases fail the stricter no-skip verdict even when the child exits zero. Platform-conditional cases are not falsely counted as Linux PASS. This initial controller does not yet provide complementary native Windows coverage; a failed Linux no-skip result remains adverse evidence, not a product-regression claim.

Push registration is restricted to `ci/offline-intake-validation` and this workflow path. `workflow_call` and `workflow_dispatch` are available in the file. GitHub may require default-branch registration before manual dispatch; the branch-specific push path supplies the first run without changing master, the reviewed source branch or existing upstream guards. No secrets are passed or inherited. The checkout action uses a short-lived read-only GitHub token for fetching public source; validation commands do not receive it. Artifact upload uses the Actions runtime identity outside the source command environment.

Do not merge this controller into the source PR to run it. Do not use its existence or its syntax checks as delivery PASS. Read all job results and artifacts, verify their source SHA, and inspect all test summaries and skips. Any source defect needs a separate base/head runtime control. No merge, deployment, identity provisioning, paid model evaluation or production credential is authorized by this controller.
